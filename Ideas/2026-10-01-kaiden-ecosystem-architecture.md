# KAIDEN — единая цифровая экосистема

## Исходная идея

KAIDEN должен восприниматься не как отдельный персональный сайт, Telegram-архив или набор несвязанных проектов, а как единый зонтичный бренд: то, что я создаю, знаю и могу предложить.

Продукты могут наследовать бренд — например, **KAIDEN Orion**.

## Пользовательская модель

У KAIDEN есть несколько логически разных, но связанных направлений:

- **Knowledge** — открытая база знаний: ИБ, противодействие мошенничеству, AI, разработка, финансы, open source, методики, практики, исследования.
- **Tools** — полезные инструменты, плагины, open-source решения и подборки.
- **Products** — самостоятельные продукты KAIDEN, например KAIDEN Orion.
- **Services** — услуги и прикладная экспертиза.
- **Labs** — эксперименты, прототипы, исследования и разработки, ещё не ставшие полноценными продуктами.
- **About** — автор, компетенции и контекст бренда.

Knowledge не должен быть замаскированной рекламой. Бесплатные материалы должны иметь самостоятельную ценность. Коммерческие предложения связываются с ними контекстно: материал может вести к релевантному инструменту, продукту или услуге.

## Главный архитектурный принцип

**Один контент — несколько интерфейсов.**

Нельзя строить независимые базы для сайта, Telegram Mini App и Telegram-постов.

Должно существовать единое контентное ядро — условный **KAIDEN Core** — а разные поверхности только представляют одни и те же данные.

Условная сущность `ContentItem`:

- id / slug;
- title;
- summary;
- content;
- content_type;
- category;
- tags;
- sources;
- related_items;
- visibility;
- status;
- published_at / updated_at;
- author/editorial metadata.

Типы контента могут включать article, guide, methodology, tool, collection, research, news, product, service.

## Поверхности

### KAIDEN Web

Основной публичный интерфейс экосистемы.

Должен поддерживать:
- каталог и таксономию;
- полнотекстовый поиск;
- фильтры и теги;
- полноценные страницы материалов;
- связанные материалы;
- Tools / Products / Services / Labs;
- SEO и внешние ссылки.

### KAIDEN Telegram Mini App

Telegram Mini App — мобильный Telegram-интерфейс к тому же KAIDEN Core, а не отдельный архив.

Сценарий:
`Telegram → Open KAIDEN → категория → подкатегория → материал / инструмент / подборка`.

Mini App оптимизируется под быстрый поиск и навигацию внутри Telegram.

### Telegram

Telegram остаётся каналом распространения и социальной оболочкой:
- анонсы;
- новости;
- короткие версии материалов;
- уведомления;
- обсуждение / сообщество.

Публикация должна генерироваться из существующего ContentItem: короткий текст + ссылка/deep link на полную сущность.

## Внутренний контур KAIDEN_Home

`KAIDEN_Home` — не публичная CMS, а внутренняя мастерская и источник ранних материалов.

Предлагаемый lifecycle:

`Idea → Research → Specification/Project → Review → Public Knowledge / Tool / Product`

То есть мысль сначала фиксируется в репозитории, затем при необходимости развивается. Публикация в публичный KAIDEN происходит осознанно, а не автоматически.

Это позволяет использовать ChatGPT как интерфейс захвата и структурирования идей, не смешивая приватные заметки с публичной базой.

## Что хранить централизованно

В Core должны быть общими:
- контент;
- категории и теги;
- связи между сущностями;
- источники;
- статусы публикации;
- поиск;
- изображения/вложения и их metadata;
- ссылки Knowledge ↔ Tools ↔ Products ↔ Services.

Web и Mini App не должны иметь собственных копий этих данных.

## Административный контур

Нужен единый редакционный интерфейс или pipeline, позволяющий:
1. создать/импортировать материал;
2. назначить тип, категорию и теги;
3. сохранить источники;
4. связать с другими сущностями;
5. подготовить summary для Telegram;
6. проверить материал;
7. опубликовать;
8. обновлять одну сущность без ручного редактирования всех каналов.

На раннем этапе эту роль частично может выполнять Git-based workflow; отдельная CMS нужна только когда объём и редакционные операции это оправдают.

## Поиск и навигация

Для большой базы критичнее хорошая информационная архитектура, чем визуальная главная страница.

Минимум:
- глобальный поиск;
- иерархия категорий;
- теги;
- тип материала;
- related content;
- breadcrumbs;
- сохранённые/избранные материалы — позднее.

В будущем можно добавить семантический поиск и рекомендации, но они не должны заменять нормальную таксономию.

## MVP

Первая версия не должна пытаться реализовать всю экосистему.

### Этап 1 — Content Core + Web
- определить ContentItem и таксономию;
- импортировать небольшой набор реальных материалов;
- каталог;
- поиск;
- страницы материалов;
- Knowledge + Tools;
- базовые страницы Products и Services.

### Этап 2 — Telegram
- бот/точка запуска;
- Mini App поверх того же API/Core;
- категории, поиск, карточки, просмотр материалов;
- deep links;
- публикация анонсов из ContentItem.

### Этап 3 — Editorial workflow
- удобное добавление материалов;
- draft/review/published;
- импорт ссылок;
- генерация summary;
- дедупликация;
- контроль устаревших материалов.

### Этап 4 — Ecosystem
- Products / Services / Labs как полноценные связанные сущности;
- аккаунты/избранное при реальной необходимости;
- рекомендации;
- аналитика;
- дополнительные интеграции.

## Что не делать

- Не делать отдельную базу материалов для Telegram.
- Не копировать статьи вручную между Web и Mini App.
- Не превращать Knowledge в рекламный блог.
- Не строить сложную CMS до проверки реального workflow.
- Не начинать с AI-рекомендаций вместо категорий и поиска.
- Не публиковать автоматически содержимое KAIDEN_Home: приватный и публичный контуры должны иметь явную границу.

## Технический принцип без преждевременного выбора стека

На текущем этапе важнее закрепить границы компонентов, чем выбирать React/Next.js/PostgreSQL и т.п.

Целевая схема:
- единый backend/content service;
- структурированное хранилище;
- API для клиентов;
- Web client;
- Telegram Mini App client;
- Telegram bot/publisher;
- search index;
- media storage;
- editorial/admin workflow.

Конкретные технологии выбираются после определения MVP, объёма контента, модели редактирования и требований к хостингу.

## Ключевая формула

> **KAIDEN — единая экосистема знаний, инструментов, продуктов и прикладной экспертизы. Web и Telegram являются разными входами в одну систему, а KAIDEN_Home — внутренним контуром, где знания и продукты рождаются.**
