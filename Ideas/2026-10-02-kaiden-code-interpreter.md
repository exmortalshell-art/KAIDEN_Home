# KAIDEN Code Interpreter / Semantic Code Lens

Дата: 2026-10-02
Статус: идея / концепт для проработки

## Суть

Сделать слой поверх IDE (в первую очередь VS Code / Cursor), который позволяет человеку без знания языка программирования понимать открытый файл кода не через чтение синтаксиса, а через человеческое объяснение структуры, назначения и связей.

Ключевая идея: не просто `Explain this code`, а **semantic overlay над исходным кодом**.

Пользователь открывает, например, `SurfaceMap.tsx`, нажимает кнопку `Understand File` / горячую клавишу / контекстное действие и получает автоматическую декомпозицию файла на смысловые блоки.

## Базовый UX

### 1. Объяснение конкретного блока

Пользователь кликает по функции, хуку, выражению или выделенному фрагменту и получает:

- что это;
- зачем это здесь;
- что получает на вход;
- что возвращает;
- откуда приходят данные;
- куда результат уходит дальше;
- что произойдёт, если изменить или удалить блок;
- насколько изменение рискованно.

Пример:

```text
useMemo(...)

Что это:
Кэширование вычисления.

Зачем здесь:
Построение карты дорогое, поэтому код не пересчитывает её при каждом рендере.

На человеческом:
Если входные данные не изменились — используй уже готовый результат.
```

### 2. Режим «рентген файла»

Команда `Understand File` сама делит файл на логические зоны, например:

```text
SurfaceMap.tsx
│
├── Imports
├── Component state
├── Data loading
├── Scenario handling
├── Graph construction
├── LOD
├── Culling
├── Event handlers
└── Render
```

Каждый блок кликабельный и ведёт к соответствующим строкам кода.

Для каждого блока можно показывать короткое человеческое описание прямо поверх/рядом с кодом.

## Главное отличие от обычного AI Explain

Обычный Cursor/AI Assistant предполагает, что пользователь уже понимает:

- что именно нужно выделить;
- какой вопрос задать;
- какой участок важен;
- является ли код отдельным логическим блоком;
- что опасно менять;
- какие зависимости существуют вокруг него.

KAIDEN Code Interpreter должен самостоятельно определять логические блоки и объяснять их значение в контексте всего проекта.

То есть задача — не «объяснить выделенный текст», а **дать человеку ментальную модель кода**.

## Связка с KAIDEN Architecture Flow Viewer

Самая сильная часть идеи — двусторонняя связь IDE и архитектурной карты.

Сейчас Architecture Flow Viewer решает направление:

```text
код → архитектурная карта
```

Code Interpreter добавляет обратный сценарий:

```text
открытый код → локальная архитектурная карта + человеческое объяснение
```

И затем связывает оба интерфейса:

```text
IDE ↔ Architecture Map
```

Пример сценария:

1. Пользователь открывает `SurfaceMap.tsx`.
2. Нажимает `Understand File`.
3. Получает структуру файла и смысл блоков.
4. Нажимает `Показать на Architecture Map`.
5. KAIDEN открывает соответствующий узел на общей карте системы.
6. Пользователь видит зависимости, маршруты, риски, сценарии и соседние компоненты.
7. Из Architecture Map можно вернуться обратно в конкретный файл/функцию IDE.

## Возможные режимы объяснения

### Beginner

Для человека без знания программирования.

Минимум терминов, максимум причинно-следственных объяснений.

### Technical

Для разработчика: типы, зависимости, lifecycle, data flow, side effects, complexity.

### Architecture

Объясняет не синтаксис, а роль блока в общей системе.

### Risk / Change Impact

Отвечает на вопрос:

> Что я потенциально сломаю, если изменю этот участок?

## Важные функции

- автоматическая сегментация файла на смысловые блоки;
- inline semantic labels;
- Explain Block;
- Understand File;
- Explain Dependency;
- Where does this data come from?;
- Where does this result go?;
- Change Impact;
- Risk Score;
- переход `код → карта`;
- переход `карта → код`;
- поддержка task-first сценариев;
- использование данных truth pipeline Architecture Flow Viewer;
- индексирование workspace/repository для контекстных объяснений.

## Техническая форма

Предпочтительно не делать отдельную IDE.

Первая реализация — **расширение VS Code / Cursor** с использованием:

- CodeLens;
- hover providers;
- decorations;
- sidebar/webview panel;
- commands/context menu;
- symbol/navigation APIs;
- LSP/AST/tree-sitter для структурного анализа;
- KAIDEN truth pipeline для проектного контекста;
- LLM для человеческого объяснения.

## Ключевая продуктовая формулировка

> IDE-режим для человека, который способен проектировать и управлять программой через AI, но не обязан уметь читать исходный язык программирования.

Или короче:

> **KAIDEN Code Interpreter — переводчик между исходным кодом и человеческой моделью системы.**

## Почему идея важна

Современные AI IDE хорошо генерируют и объясняют код, но всё ещё требуют от пользователя хотя бы базового понимания того, куда смотреть и что спрашивать.

KAIDEN может закрыть именно этот разрыв: сделать кодовую базу обозримой для владельца продукта, архитектора, аналитика или AI-native разработчика без необходимости сначала становиться полноценным программистом.

Это логично продолжает Architecture Flow Viewer и потенциально превращает его из внешней карты проекта в полноценный навигационно-объяснительный слой между человеком, AI и кодовой базой.
